# Connection security and operation

Organisation owners manage forge, model, agent and delivery connections. `/api/v1/orgs/{orgID}/connections` lists all kinds; `/connections/forges`, `/models`, `/agents` and `/delivery` provide typed creation/list routes. Detail, test, rotate, rewrap, revoke and private-route operations use `/connections/{connectionID}`. Mutations require the session CSRF token, exact Origin and quoted `If-Match` version. Secret inputs never appear in responses. Rotation invalidates all capability evidence; revocation destroys the encrypted credential and disables the route. No provider is healthy until its registered adapter has checked it.

Self-hosted encryption uses a random per-credential AES-256-GCM data key wrapped under the operator key. Both layers authenticate the organisation, connection and credential version. Set `REFORGE_ENCRYPTION_KEY` to a base64-encoded 32-byte random key and preserve it separately from database backups. Hosted startup requires the AWS KMS backend described in `t03-kms.md`; it cannot fall back to an operator key.

For self-hosted wrapping-key rotation, configure `REFORGE_ENCRYPTION_KEY_ID` and `REFORGE_ENCRYPTION_KEYS` (JSON map of key ID to base64 key), retaining the old key during migration. Restart, invoke `POST /connections/{id}/rewrap` for each credential using its current version, verify restore/decryption, then remove the old key. Rewrap changes the wrapping key without changing the provider credential. For provider credential rotation use `POST /connections/{id}/rotate` with a new write-only `secret`, then test capabilities again. Keep required old wrapping keys with historical backups.

Configured private endpoints require an explicit owner-approved runner, exact hostname and CIDR list. Enrollment is checked transactionally. Public control-plane requests cannot reuse a private route. Until T07's authenticated runner and fixed-operation broker are registered, route approval returns `runner_required`; no fabricated runner or successful test is recorded. Custom CAs supplement system roots without disabling hostname validation.

`ResolveTx` is an internal one-operation primitive: controllers must hold current org/connection authority, job fence and policy locks at dispatch, use the returned fixed-origin client and discard the plaintext immediately afterward. It is not exposed through HTTP. Capability probers must use the supplied context/client and return classified metadata, never raw response bodies. Public probes run under current identity/connection locks with a ten-second context. Raw provider errors are discarded; known credential values are redacted from returned metadata. Later job/broker tickets enforce these same boundaries for long-running model and forge operations.

Subscription connections store no copied OAuth/access token. They remain disabled with an actionable runtime/entitlement requirement until T16 proves a documented permitted route. API connections explicitly select `direct_api`; no fallback changes billing route.

Local checks cover persisted ciphertext, tenant and connection bindings, restore, credential and wrapping-key rotation, stale versions, revoked credential rejection/deletion, failed-probe redaction, queued probe versus revocation, route timestamp tampering, and transport destination enforcement. Actual enrolled private connectivity remains T07/T11/T15/T27; external AWS KMS permission/key recovery certification remains outstanding.
