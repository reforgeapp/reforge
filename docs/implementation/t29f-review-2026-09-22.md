## Qualitative review

- Inventory routes now have one toolbar, a dense searchable table and a persistent detail
  that keeps list context; modals are limited to create/edit and confirmation.
- Health, capacity, trust, version, route count and heartbeat are API-backed or visibly
  unknown; no value is inferred from login.
- Disabled actions name the missing prerequisite (for example an unapproved agent runtime
  or a pool with no repository authority).
- Remaining rough edges: the Runners list still shows non-representative records in the
  shared development organisation (the demo organisation is clean); long detail panels
  scroll; narrow tables scroll horizontally rather than reflowing to list rows.

## Representative task paths

- Find and enrol a runner: search a pool by name → Open → Enrol runner (3 interactions).
- Inspect a connection: choose a tab → Open → read capability/billing (2 interactions).
- Inspect a finding: select the row → read evidence and repair preview (1 interaction).
- Inspect a run: select the row → read stages, frozen checks and artifacts (1 interaction).
