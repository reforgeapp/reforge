# T28c dependency and distribution inventory

Inventory generated on 2026-09-23 with `python3 scripts/dependencies.py`. It reads pinned versions from `go.mod`/`go.sum` and `web/package-lock.json`, uses `go list -deps` on all four shipped Go binaries and `go list -deps -test ./...` for package scope, then copies exact-root `LICENSE`, `COPYING`, and `NOTICE` files from the versioned module/package sources. It trims trailing line whitespace only. `dependencies.md` is the per-version manifest; `third-party-notices.txt` contains the collected texts. Go licence identifiers are not inferred from copyright headers.

The Go graph contains 153 modules. The four shipped binaries use 66 modules; the repository test package graph adds no further module versions. The other 87 graph entries are fetched by the Docker build stage’s `go mod download`, but no packages from them appear in the shipped binary or repository test package graphs. All 153 exact module roots had a `LICENSE` or `COPYING` file in the hydrated Go module cache; all found licence and notice files are included in `third-party-notices.txt`.

The npm lock has 98 packages: 15 production packages are eligible for the compiled web bundle copied into the control image; 83 are marked development-only and are not copied as installed packages. Exact package metadata and available root notices are listed. Twenty-nine development-only packages declare a licence in the lock but have no top-level licence/notice text in their package root. One Rolldown binding has defensible sibling evidence from `rolldown@1.2.9`: lock metadata matches repository URL, repository directory, version, and declared licence; that shared text is retained under the sibling package heading. The remaining 28 have metadata only (`dependencies.md` identifies each); they are not part of the shipped web bundle, but remain explicit evidence gaps if future builds distribute them.

Container distribution has separate unresolved evidence. The current final image inputs are `alpine:3.21` for control and runner, `nginx:1.27-alpine` for docs, and `postgres:18.6-alpine` in Compose. Control and runner install Alpine `ca-certificates`; runner also installs `git`. The docs image copies built MkDocs output into nginx. Build stages use `node:26-bookworm`, `golang:1.27-bookworm`, and `python:3.14-slim`; docs installs `mkdocs-material==9.7.0` without a Python lockfile. Base-image, OS-package, and Python transitive notices are not in the collected text file. The runner and control Go binaries use `CGO_ENABLED=0`; Go module source trees are not copied into final images.

The references below pin the locally available base and Compose images. Before public image publication, collect SBOM and notices from the exact OCI manifests including installed OS packages, and lock the docs Python transitive set before collecting its notices. Re-run this inventory for the release commit and published image digests. Licence text presence is evidence, not a legal classification or publication authorisation. This inventory makes no blanket licence-family conclusion; owner/legal release review remains open.
