# Organisation OIDC invitations

Owners invite a normalized verified email with a selected role and bounded expiry. Creation returns one high-entropy fragment URL once; browsers keep token out of HTTP requests, proxy logs and referrers. The database retains only its SHA-256 token hash. Invite lists and revocation never return token material. Invitation API mutations require tenant session, CSRF, current owner authorization and audit records.

The `/invite#token=...` fragment exists only in the browser. The GUI reads the token, removes the fragment before navigation, then POSTs it as a bounded same-origin `application/x-www-form-urlencoded` body. Successful redemption returns `200` JSON containing `authorization_url`; the GUI navigates there after validating its HTTP(S) scheme. This same-origin fetch avoids the global `form-action 'self'` CSP blocking a form redirect to the configured identity provider. Server rejects tokens in request URLs and sets `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on every redemption response. Access logging records route templates only. Start requires an unredeemed, unexpired invitation and the same active, verified issuer config ID, version and issuer that were active when the owner created it. Rotation makes unused links invalid. OIDC state, browser binding, nonce, PKCE verifier, invitation ID/hash and current config ID/version are stored server-side and expire within ten minutes. Callback requires signature, audience, issuer, nonce, state, browser binding and PKCE validation plus `email_verified=true`. Email comparison uses the same lowercase/trim normalization as invitation creation. No email-domain matching, email-only account link, pre-membership tenant session or cross-organisation grant is allowed.

After token validation, one transaction locks and rechecks the invitation, active configuration and exact tenant. It resolves only the exact (issuer, subject) identity or creates that identity, then creates the invited membership and an organisation/config-version-bound session and marks the invitation redeemed. Any failure rolls back all writes. Existing member identities cannot gain duplicate membership through an invite; revoked, expired, replayed, rotated-provider and mismatched-email attempts fail. Runtime role has no RLS bypass; invitation token hash is a narrow pre-auth RLS capability.

Restricted-role PostgreSQL/runtime tests cover owner-only management, exact email normalization, bounds, one-time token disclosure/hash-only persistence, expiry, role scope, verified-email mismatch, unverified email, exact pre-auth row visibility, tenant separation, callback replay/concurrency, provider disable/rotation and absence of user/membership on failed claims. HTTP tests assert route registration, missing/cross-site Origin rejection, query-token rejection, no token echo, no-referrer and no-store headers. PostgreSQL tests must run with forced RLS and the restricted runtime role against disposable migrated storage. Local signed-IdP fixtures are contract evidence only; hosted tenant IdP certification remains external.

## Local evidence

TestOrgOIDCRuntimeLoginCallback passed with migration 036 applied to a clean disposable PostgreSQL database and a runtime role that is not owner and has no RLS bypass. Its local signed issuer covers owner denial, token-hash-only persistence, owner/reviewer repository scope, verified-email membership/session creation, mismatched and unverified email rejection without account creation, expiry, replay, concurrent redemption, cross-tenant rejection, pre-auth single-row RLS visibility, and issuer rotation/disable. A stale unused invitation cannot start after rotation even after the new provider version is active. TestOrgOIDCPostgresContract, TestOrgInvitationRoutesAreRegistered, race detection, and go vet ./internal/auth ./internal/httpapi passed. This test fixture does not certify hosted identity-provider behavior.

Strict-CSP connected browser acceptance passed with a local signed IdP and no API interception or CSP bypass. Owner UI created and copied an invitation, showed acceptance after reload, and revoked a second pending invite. Invitee redemption created one verified identity, reviewer membership and organisation session; replay and revoked-link redemption returned 401 without extra membership. Fragment was removed before redemption; token did not appear in request URLs, server logs or browser storage. Keyboard acceptance and dialog Escape behavior passed; 390px light/dark owner and invite views had no horizontal overflow. This local signed issuer is contract evidence only; hosted IdP certification remains external. Invite management GUI, one-time copy dialog and invitee landing page are implemented.
