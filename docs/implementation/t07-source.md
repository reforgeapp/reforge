# T07.4 — Pinned source acquisition

`ForgeSource.ReadSourceManifest(ctx, repository, commitSHA)` returns the immutable repository identity, exact commit, explicit object format, proof kind, directory/file entries and completeness. Native adapters accept full lowercase SHA-1 commit IDs. No branch, clone URL, archive extraction, host Git process, hook, submodule or LFS filter runs during acquisition.

| Provider | Native reads | Proof |
| --- | --- | --- |
| GitHub | Repository identity; Git commit; one recursive Git tree read addressed by root tree SHA | `commit_tree_hash`: every subtree and the native commit's root tree hash are reconstructed |
| GitLab | Repository identity; exact commit ID; recursively paginated repository tree with `ref=commitSHA` | `immutable_ref_api`: provider-attested immutable commit addressing, verified pagination, subtree hashes and file blob hashes; no claimed native root hash |
| Gitea 1.27.3 | Repository identity; exact commit ID; commit-addressed recursive tree with page, total count and truncation checks | `immutable_ref_api`: this version returns the **commit ID** in both `commit.tree.sha` and the root tree response's `sha`; neither is a root tree object hash |

GitHub reads the recursive tree in one request so large repositories fit the read budget; `truncated: true` or a missing flag is rejected, and the root tree hash is rebuilt from every entry. GitLab requires native page/per-page metadata, sequential next pages, consistent totals when supplied and a provably final page. Gitea verifies the pinned commit identity on every page, stable total count, page number, progress and final entry count. All profiles stop at 10,000 entries and reject malformed or duplicate entries.

`source.Fetch(ctx, source.Reader{Manifest: ..., File: ...}, repository, commitSHA)` returns a complete `sandbox.Snapshot` only after validation. Reader callbacks are trusted control-plane operations, bound to the authorized tenant, repository, connection and route. They must use the fixed public/private provider gateway and current authorization; a browser cannot supply a manifest, source callback or completeness assertion. Credentials remain outside the sandbox. T19 connects these callbacks to its current lease and policy checks.

The verifier reconstructs Git tree objects in native byte ordering, verifies every explicit directory hash, verifies a native root hash when that proof exists, and checks each regular file's Git blob hash. GitLab's raw-file API need not supply a redundant blob SHA because the returned bytes are hashed against the manifest entry. Commit-to-tree/ref binding is attested by the authenticated native API; this implementation does not claim independent verification of a raw Git commit object or signature. The returned canonical SHA-256 snapshot digest binds file paths, bytes and executable flags. Controllers should retain the manifest/proof as acquisition evidence.

Limits are 10,000 total entries, 4 MiB per file, 64 MiB total file bytes, 1,024-byte paths and fewer than 64 separators. Symlinks, submodules, unknown modes/formats/proofs, duplicate or case-colliding paths, traversal, control characters, invalid UTF-8 and any `.git` path component are rejected. Directories are structural manifest entries; the file snapshot materializes parent directories through its files. Empty file snapshots are rejected by the existing sandbox contract. The pure verifier supports explicitly selected SHA-256 Git objects, but no native SHA-256 provider profile is currently qualified. Source bytes are copied before entering the snapshot; cancellation is checked around every callback and throughout validation.

Checks cover object ordering, executable mode, SHA-1/SHA-256 validation, corrupt bytes, missing files/directories, root/subtree mismatches, identity changes, unsafe paths/modes, duplicate/case collisions, unknown proofs, mutable refs, cancellation and byte/count limits. HTTP fixtures exercise GitHub tree truncation and GitLab/Gitea pagination failures. A real local Gitea 1.27.3 test creates a disposable private repository with 105 files, verifies two-page acquisition, advances the branch and confirms all acquired bytes still belong to the pinned commit; it deletes the fixture afterward. No external customer repository or paid provider is used.

Run the local contract with `REFORGE_GITEA_TEST=1 REFORGE_TEST_ROOT=/path/to/reforge go test -race ./internal/forge/gitea -run TestRealGiteaPinnedSourcePaginationAndBranchMovement -count=1`. The fixture reads the ignored local admin token without logging it and requires the pinned loopback instance. Public GitHub/GitLab live qualification and T19 gateway/runner composition remain integration work.
