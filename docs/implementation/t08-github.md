# T08 GitHub adapter

`internal/forge/github` implements inventory, verified webhook decoding, checks, pull requests, App authentication, guarded branch publication, protection inspection and guarded native merge/queue operations. Fixture qualification is complete; live GitHub Cloud and GHES certification remains open.

## Construction and authority

`New(forge.Config)` requires an explicit transport, endpoint and token; it supports reads. Owned writes require `NewApp(ctx, cfg, AppConfig{AppID, InstallationID, PrivateKeyPEM})`. App authentication validates the App and installation IDs, suspension state, token expiry and immutable bot actor ID. RSA signing uses Go's standard cryptography. Tokens refresh under a shared lock before expiry; refresh has a 15-second deadline, never falls back to expired credentials, and rejects changed bot identity. Unauthorized responses invalidate the cached token without replaying mutations. Private keys are excluded from JSON and formatted logging. GitHub documents RS256 App JWTs and short-lived installation tokens. [App authentication](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-json-web-token-jwt-for-a-github-app), [installation authentication](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation).

The connection factory supplies SSRF-controlled REST and GraphQL transports separately. Cloud uses REST `https://api.github.com` and GraphQL `/graphql`; GHES uses REST `/api/v3` and GraphQL `/api/graphql`. `WithGraphQL(endpoint, client)` requires the same origin and an exact GraphQL path. No environment credential discovery or proxy configuration occurs here. HTTP clients reject redirects, requests have bounded deadlines and responses are limited to 4 MiB. REST pins `2022-11-28`, currently supported through March 10, 2028; GHES feature availability still requires version-specific qualification. [API versions](https://docs.github.com/en/rest/about-the-rest-api/api-versions).

Controllers install `WithBranchAuthorizer`, `WithChangeAuthorizer`, `WithReviewAuthorizer` and `WithMergeGuard`. Every native side effect requires its callback. These callbacks must reload persisted tenant/repository authority, workflow fence, pause/revocation state, operation intent and current policy within the controller's mutation transaction. Merge guards additionally resolve `GateID` to exact H/B/T evidence, check `RulesHash`, required App policy-check identity and provider qualification. A callback alone does not establish native enforcement.

## Provider behavior

Installation inventory decodes the repository wrapper. Lists validate bounded, strictly advancing cursors; incomplete pages fail closed. Empty files are valid. Pull request repository identity comes from `base.repo`; reads refresh the target ref. Operation reconciliation requires the authenticated App's immutable bot actor plus operation marker, immutable repository identities and exact branches. Duplicate matching objects conflict. PR creation preflights H and validates the returned object; an ambiguous response requires reconciliation. No undocumented idempotency header is used.

`UpdateAppBranch` accepts bounded edits to an authorized `reforge/` branch. Creation uses an immutable repository node ID and native ref uniqueness. Commit publication uses the immutable ref node ID and `expectedHeadOid`; existing branches must match the supplied old head. The operation marker correlates the resulting commit but does not make GraphQL retries idempotent. No force update is issued. [GraphQL Git operations](https://docs.github.com/en/graphql/reference/git).

Protection combines classic rules and applied rulesets, preserving required check App IDs, approvals, CODEOWNERS, strict target behavior, merge methods and queue requirements. Latest failing checks override older successes; wrong publishers and stale approvals block. Incomplete protection, unknown rules, unbound check publishers, hidden bypass lists and administrative authority uncertainty remain blocked. Ruleset bypass actors can be omitted without write visibility; this is not interpreted as an empty list. Do not elevate the operational App to obtain that visibility. Classic-protection 404 on a protected branch also remains blocked pending an independently qualified inspection path. [Rules API](https://docs.github.com/en/rest/repos/rules).

Direct merge sends exact H and requires native strict target enforcement, an App-bound required check and a qualified execution guard. REST does not provide an atomic expected-B parameter: versions/topologies without demonstrated target-advance rejection or retesting must stay disabled. Queue admission uses immutable PR identity, exact H and no queue jump; the method must match native queue configuration. Existing queue entries are observations, not proof of this operation's authorship. Mutation transport failures are uncertain and never automatically retried. Successful direct merges require canonical outcome reconciliation. [Merge API](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request).

Queue reads never invent `TestedSHA` from the PR head. Verified `merge_group` webhooks retain the combined candidate head; durable association with base/predecessor evidence and execution-time App gate publication belong to T11/T21. Queue cancellation and deployment operations are not implemented here. Native writes remain capability `unknown` until per-repository qualification; deployment capability is `unsupported`. [Merge-group events](https://docs.github.com/en/enterprise-cloud%40latest/webhooks/webhook-events-and-payloads).

## Validation and remaining qualification

Package race tests and vet pass. Fixtures cover signed JWTs, concurrent refresh, wrong installation/bot identity, pagination, empty files, spoofed ownership, duplicate operations, immutable-ref CAS, revocation between side effects, bypass visibility, incomplete rules, wrong/newly failing checks, stale reviews, target drift and native queue guards.

Before enabling native writes, qualify a dedicated Cloud test organisation and each claimed GHES release separately: selected-repository App permissions and revocation; hidden/inherited protection; concurrent source movement during publication; target advancement between admission and merge; same-named spoofed checks; queue `merge_group` evidence; policy changes after admission; cancellation races; and timeout/restart reconciliation. Record actual native outcomes and enforcement artifacts. No external credentials or live provider mutations were used for this slice.
