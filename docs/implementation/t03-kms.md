# T03 hosted AWS KMS wrapping

Status: implemented and fixture-verified; live AWS key-policy, IAM-role and recovery certification remains pending.

Hosted startup uses `secrets.NewKMS(ctx, KMSConfig{Region, KeyID, PreviousKeyIDs})`. Configure `REFORGE_KMS_REGION`, `REFORGE_KMS_KEY_ARN` and optional comma-separated `REFORGE_KMS_PREVIOUS_KEY_ARNS`. Supply immutable full symmetric KMS key ARNs in the configured region; aliases are rejected. The AWS SDK standard credential chain supports environment/shared credentials and deployed IAM identities. Missing credentials fail startup with an actionable message. Startup retrieves credentials but performs no KMS encryption/decryption preflight. Self-hosted deployments retain `secrets.New` and their operator keyring. [AWS credential configuration](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-gosdk.html).

Each credential retains AES-256-GCM value encryption with a new random 256-bit data key. KMS Encrypt wraps that data key; KMS Decrypt unwraps it. Both calls specify the approved key ARN and the same encryption context containing organisation ID, connection ID, credential version and purpose. No credential value appears in that context. The value's existing AEAD binding remains enforced. Hosted envelopes use version 2 and persist the exact KMS key ARN; operator-key envelopes retain version 1. Neither backend falls back to the other. [KMS Encrypt](https://docs.aws.amazon.com/kms/latest/APIReference/API_Encrypt.html), [KMS Decrypt](https://docs.aws.amazon.com/kms/latest/APIReference/API_Decrypt.html).

`SealContext`, `OpenContext` and `RewrapContext` preserve request cancellation and enforce a five-second whole-operation deadline. Existing `Seal`, `Open` and `Rewrap` remain bounded compatibility wrappers. AWS calls use the official Go SDK with bounded HTTP requests/retries, default AWS endpoint resolution, no endpoint override/proxy/redirect and no request-body logging. Decryption only calls KMS for configured current/previous keys; response key ARN, symmetric algorithm and 32-byte plaintext key are checked. Provider errors are classified without returning raw AWS error text. Temporary plaintext data-key buffers are cleared after use.

For wrapping-key rotation, configure the new current ARN and keep the old ARN in `PreviousKeyIDs`. Rewrap stored envelopes with their unchanged organisation/connection/credential-version binding and persist each result atomically. The encrypted credential value remains byte-for-byte unchanged. Remove the old ARN from the allowlist only after all envelopes and required backups can be restored using retained keys. The deployed IAM principal needs `kms:Encrypt` on the current key and `kms:Decrypt` on every retained key; key policies must permit that principal. No key creation, policy editing or cloud deployment is performed by this implementation.

Verified with injected SDK-compatible Encrypt/Decrypt fixtures: context/tenant/connection/version binding, current and previous key restrictions, envelope rotation, ciphertext tampering, malformed key responses, cancelled/deadline-bound requests, sanitized AWS errors, data-key clearing, missing startup credentials, legacy-backend separation and rejection of mutable key aliases. `go test -race ./internal/secrets`, `go vet ./internal/secrets`, and compilation/tests for `internal/connections` and `cmd/server` passed. No live paid KMS API call was made. IAM permission correctness, live encryption/decryption, managed-key rotation and backup restoration require an explicitly authorized AWS qualification environment.
