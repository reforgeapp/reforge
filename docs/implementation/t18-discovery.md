# T18 discovery and cooperation

Discovery uses scoped persisted inventory, fresh connection metadata, canonical native changes/checks and verified blobs at immutable commits. Polling runs automatically; maintainers may queue a refresh. A durable tenant cursor, fenced leases and atomic complete snapshots prevent partial or superseded scans from resolving findings. Unsupported/auth failures require connection correction and explicit retry; transient failures retry with delay.

Fingerprints include tenant, repository, connection, source, target branch and exact dependency group/ranges. Changed evidence invalidates dismissal/snooze; unchanged evidence preserves suppression until snooze expiry. Retargeting and changed groups supersede previous findings. Assignments require current repository access. Every mutation uses version checks, tenant RLS and scoped audit/events.

Trusted Renovate/Dependabot identities are native immutable actor IDs configured by repository administrators. Display names and branch names confer no authority. Human and unknown ownership remain explicit; all head changes invalidate repair evidence. In-place edits remain unavailable until provider exact-ref and head-ownership certification exists. Requested Reforge merge authority retains a separate blocker until bot automerge cooperation is qualified. Discovery never rewrites bot configuration.

Repair admission rejects incomplete/stale evidence, overlapping open bot groups and active repairs, including completed tasks whose native change remains active. The repair controller must retire bindings only after it reconciles known terminal publication state. Imported advisories remain reported evidence until independently reproduced; input completeness is not security verification. Missing bot configuration produces a reviewable Renovate onboarding finding, without provider mutation.
